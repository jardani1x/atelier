# Limitations

ATELIER does not reproduce all of AutoCAD, SketchUp or Enscape. This list covers brief items that are missing or only partly done.

## Not implemented

**3D modelling:** a free 3D line tool; boolean cuts (a shape drawn on a face is a separate extruded solid and does not carve the face; pushing into a solid only thins that solid); SketchUp-style inference beyond corner snapping. The orthographic toggle covers orbit view only; walkthrough, path tracing, panoramas and tours switch back to perspective.

**Rendering:** scanned PBR maps (normal and roughness maps are estimated from image brightness). Bloom and ambient occlusion apply to the interactive view and its screenshots only, not to path tracing, tours or panoramas. Ambient occlusion treats glass and see-through walls as solid, and bloom only shows on surfaces brighter than diffuse white. Ceiling-light brightness was tuned by eye on one bedroom under software WebGL, so use the intensity control for other rooms. The denoiser is a screen-space filter and softens fine texture at low sample counts.

**Walkthrough and output:** tour video records the rasterised view in real time at canvas resolution, not path traced frames. It is WebM in Chromium and Firefox (MP4 where only that is available). A slow GPU plays the tour slower instead of skipping frames, so the file can run longer than the nominal 4 s between views. Only WebM output in software WebGL Chromium has been tested. Walkthrough stays at floor level, so stairs cannot be climbed and are not obstacles. Windows block the walker. Drawn solids collide by bounding box, so a rotated or round solid blocks slightly more space than it occupies. The 360 panorama is rasterised, not path traced, and there is no in-app panorama viewer. Its photo sphere metadata is checked in tests but the file has not been opened in an external 360 viewer.

**File formats:** IFC and STL. SKP is not supported and no SketchUp compatibility is claimed.

## Partly done or unverified

- GLB and OBJ exports are checked by parsing the output in tests. They have not been opened in SketchUp, Blender or other applications, so round-trip behaviour is undocumented by testing.
- Rendering was only tested in Chromium with SwiftShader software WebGL. No test ran on a real GPU, and no FPS figure exists for real hardware.
- The 4-room HDB template is illustrative. It is not an official HDB plan and must not be used for submissions or renovation approval.
- Floor plan image calibration exists in the code from the foundation, but ATELIER added no dedicated test for that manual trace workflow.
- Automatic floor plan import has only been tested on synthetic plans generated by the tests. Accuracy on real plans is unknown. It finds straight horizontal and vertical walls only: angled and curved walls are left out and trigger a warning when enough wall ink goes unmatched. Doors and windows are read from gaps between collinear walls, so they can be confused, and door swing is not read. Rooms, furniture and text labels are not read. Photos and low-contrast scans are expected to do worse. Walls get a fixed 280 cm height. Import refuses a floor that already has walls. Password-protected PDFs are refused. Processing is local, no AI service is used.
- Cloud save and sign-in logic is unit tested against a fake backend. The automated tests have not exercised a real Supabase project, and row-level security has not been verified by a test.
- Viewport effects: the sky reads paler with effects on, ambient occlusion is weak in interior corners because it was tuned on one exterior view under software WebGL, and some noise can appear along wall seams.

## Leftovers from the foundation

- OpenPlan3D still appears in server and service error strings (`src/lib/server/*`, `services/*`), `utils/interchange.ts`, `projectPackageZip.ts`, render-lab, `assistant.connector`, and the `projectService.*` locale strings that are matched against those errors.
- The upstream README body and other upstream documents are kept and describe OpenPlan3D.
- `?import=CODE` in the editor fetches from the upstream Firebase Storage bucket (`src/routes/editor/+page.svelte`). It runs only when that URL parameter is present. Remove it before any public deployment.
- Analytics and Firebase hosting configuration from upstream remain in the repository.

## Deployment

ATELIER has not been deployed. It is run locally.
